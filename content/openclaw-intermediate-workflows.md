# OpenClaw ขั้นกลาง: จากแชตหนึ่งครั้งสู่ Workflow ที่ทำซ้ำได้

ผู้เริ่มต้นมักใช้ OpenClaw ถาม–ตอบทีละเรื่อง ระดับกลางเริ่มเมื่อเราแยกงานเป็นขั้นตอน เก็บกฎใน workspace ใช้ skills สำหรับงานซ้ำ และกำหนดว่าอะไรต้องขออนุมัติก่อนออกนอกเครื่อง

## โครงสร้างระดับกลาง

หนึ่ง กำหนดบทบาทของ Agent และขอบเขตข้อมูล สองเขียน workflow ที่มี Input, Steps, Quality Gate และ Output สามเลือก channel ที่ใช้รับส่งงาน สี่บันทึกเฉพาะความจำที่จำเป็น ห้าตรวจผลด้วยหลักฐาน เช่น ไฟล์ รายงาน หรือสถานะจากระบบจริง

## ตัวอย่าง Workflow รายงานเช้า

Input คือหัวข้อที่ต้องติดตามและเวลาอ้างอิง Steps คือดึงข้อมูลจากแหล่งที่อนุญาต ตรวจเวลา เปรียบเทียบกับวันก่อน สรุปเป็นรูปแบบคงที่ Quality Gate คือตัวเลขตรง แหล่งข้อมูลชัด และไม่เดาข้อมูลที่หาย Output คือรายงานฉบับเดียวส่งให้ผู้ใช้ตรวจ

## เลือก Heartbeat หรือ Cron

Heartbeat เหมาะกับการรวมหลายการตรวจที่เวลาเลื่อนได้และต้องใช้บริบทสนทนา Cron เหมาะกับเวลาที่ต้องตรง งานแยกอิสระ หรือ reminder ครั้งเดียว อย่าสร้าง job หลายตัวเมื่อ checklist เดียวรวมงานได้

## Checklist

มีเจ้าของงาน / แหล่งข้อมูล / เวลาและ timezone / approval gate / error handling / หลักฐานสำเร็จ / วิธีหยุดงาน / ช่องทางแจ้งปัญหา

ก้าวแรกวันนี้คือเลือกงานซ้ำหนึ่งงาน เขียน workflow เพียงหนึ่งหน้า และทดลองด้วยข้อมูลจำลองก่อนเปิด schedule จริง

แหล่งข้อมูลทางการ: https://docs.openclaw.ai และเอกสาร workspace ของ OpenClaw ที่ติดตั้งในระบบ
